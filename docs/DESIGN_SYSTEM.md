# Bridge Studio — UI Foundation 1.0

D-01 задаёт оформление существующего редактора. Базовая линия — main 330302e73f7387015629b2c753bb5ab2d0943343, v0.21.0. Стили находятся в блоке UI Foundation в src/studio_template.html. Они применяются к редактору; игровой HUD собирается своим runtime.

## Цвета и поверхности

| Переменная | Назначение |
|---|---|
| --ui-bg | Общий фон и рабочее поле графов |
| --ui-surface, --ui-raised, --ui-input | Панель, карточка/кнопка, поле ввода |
| --ui-text, --ui-muted, --ui-subtle | Основной текст, пояснения, вторичные подписи |
| --ui-accent, --ui-blue | Основное действие, дополнительный акцент |
| --ui-warning, --ui-danger | Требуется внимание, удаление/остановка |
| --ui-border, --ui-divider | Граница элемента, разделитель секций |
| --ui-hover, --ui-active, --ui-selected | Наведение, нажатие, выбранный элемент |
| --ui-disabled, --ui-focus | Прозрачность недоступного элемента, рамка клавиатурного фокуса |

Фон — тёмно-синий. Бирюзовый выделяет активную вкладку, инструмент и основное действие Build. Play и Stop имеют собственные состояния. Не передавать смысл одним цветом — сохранять название действия, категорию узла и подпись порта. Для новых элементов использовать семантические переменные, включая имеющиеся совместимые алиасы --panel, --txt, --line и --accent.

## Размеры и взаимодействие

Шкала --ui-space-1…5 соответствует 4, 8, 12, 16 и 24 px. Скругления --ui-radius-sm, --ui-radius и --ui-radius-lg — 5, 8 и 12 px. --ui-control задаёт высоту обычной кнопки/поля 32 px. Порт — компактная точка 24 px с title. Тени --ui-shadow и --ui-shadow-float используются для карточек и плавающих панелей.

Основной текст — Segoe UI/system-ui. Контролы 12 px, разделы 10 px, название выбранного объекта 15 px. Сокращённые имена ресурса допустимы только при понятном контексте; имена ассетов и графов переносятся. Для чисел использовать tabular-nums. Видимый фокус — сплошная рамка 2 px с отступом 3 px. Не заменять кнопку div-элементом. Состояние disabled задавать HTML-атрибутом.

## Оболочка

Верхняя панель состоит из строки проекта и строки рабочих команд. --ui-header равен 104 px на проверенных desktop-разрешениях. Workspace и Logic Canvas используют ту же переменную. --ui-left и --ui-right задают ширины боковых панелей с уменьшением до 1400 px. Содержимое панелей прокручивается отдельно. Toolbar 3D переносит кнопки, когда не помещается в ширину viewport.

Селекторы новых панелей должны быть ограничены редактором. Особенно осторожно изменять .panel, потому что это также имя типа UI-превью. Атрибут hidden должен сохранять действие при заданном display — для зависимых полей Logic Controls используется явное правило [hidden].

## Visual Logic

| Категория | Цвет | Класс/тип |
|---|---|---|
| Event | Бирюзовый | .logic-event, старт графа |
| Condition | Оранжевый | .logic-condition, типы if* |
| Action | Синий | .logic-action |
| Signal | Фиолетовый | .logic-signal, emitSignal |

Категория подписана текстом и обозначена верхней полосой. Выбранный узел получает обводку. Выход «Нет» отличается пунктирной линией; активная связь выделяется толщиной. Во время выбора цели выход получает состояние pending. Отсутствующая цель или неизвестный тип обозначены пунктирной границей и пояснением title.

drawLogicWires использует фактические координаты DOM-портов относительно logicGraphSurface. Изменение padding узла не должно требовать новых числовых смещений проводов. Размер поверхности 1500 × 900 и координаты узлов в документе сохраняются. Для большого графа используются обе полосы прокрутки. Узел перетаскивается за корпус или заголовок; кнопки портов выполняют соединение.

Пустой графовый редактор объясняет следующий шаг. В Inspector выбранного узла сохраняются обычные поля данных. Удаление и отключение связей недоступны, когда узел не выбран.

## Правила будущих изменений

1. Менять исходники src и собирать временный HTML через tools/build_studio.py.
2. Проверять действия мышью и клавиатурой, а также восстановление состояния сцены после Play.
3. Проверять 1280×720, 1440×900 и 1920×1080 с включённой кнопкой обновлений.
4. В screenshot-проверках использовать реальные кадры приложения и одинаковый проект.
5. При изменениях вида графа запускать tests/design-d01.cjs и сценарии gameplay-v020/021-browser.
6. Публикуемые каталоги updates и манифест не использовать как рабочие исходники.

Сборка D-01 сохраняет номер движка 0.21.0. Активация нового подписанного выпуска является отдельным этапом.
