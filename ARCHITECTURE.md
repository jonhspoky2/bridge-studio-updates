# Техническая карта

Репозиторий содержит канал доставки и тесты. Исполняемая часть редактора каждого выпуска находится в `updates/v<версия>/studio.html`. Внешний архив Bridge-Studio-v0.18.0-UI-Inventory-Shop-Audio.zip дополнительно содержит src, build_studio.py, C#-хост, установщик, примеры и тесты. Архивный payload v0.18.0 побайтно совпадает с опубликованным HTML этой версии. BridgeLauncher.cs и BridgeUpdateService.cs совпадают между архивами v0.17.2 и v0.18.0. Сборка из старого src без переноса последующих изменений вернёт устаревший интерфейс.

| Граница | Реализация и поток данных |
|---|---|
| Windows | BridgeLauncher.cs запускает локальный HTTP-сервер на loopback. Случайный путь с токеном, список допустимых ресурсов, heartbeat и обработка закрытия окна. Three.js r128 кэшируется локально. |
| Редактор | studio-code управляет документом project, выделением, инспектором, камерой и историей. В refreshScene объекты редактора пересоздаются из документа. История хранит до 60 сериализованных снимков, поэтому крупные встроенные ресурсы увеличивают стоимость правки. |
| Сохранение | Формат rwbridge.game, версия 2. verifyLoadedDoc проверяет структуру, ID, трансформации, ссылки на ассеты и графы. normalizeDoc переносит старые встроенные GLB в каталог. cleanDoc клонирует проект. Запись .rwscene и резервные копии IndexedDB имеют разные критерии успеха. |
| Ресурсы и графика | embedded-gltf-loader читает статическую геометрию и материалы. Ресурсы проекта могут включать base64. textureFor кэширует текстуры по ID и содержимому, resetTextureCache и disposeVisual освобождают ресурсы при замене. Общая refreshScene проходит всю сцену. |
| Логика | embedded-gameplay-core валидирует графы, обрабатывает события и компоненты через вызовы игрового API. embedded-economy-core управляет каталогом, количеством предметов и покупками. UI Builder хранит элементы в массиве ui, игровой HUD строится в runtime. |
| Play и Build | gameHtml собирает данные сцены, GLB-загрузчик, ядра и runtime. Play создаёт отдельный HTML через blob URL в sandbox-iframe, игра сообщает о первом кадре через postMessage. Build экспортирует ту же игру с зависимостями выбранного профиля. exportGameDoc отбирает ресурсы по ссылкам сцены. В WARPGAME подключается auth.js платформы. |
| Физика | Персонаж, скорость по вертикали, Spawn, тесты боковых препятствий и опоры реализованы в runtime. Для ground/block/movingPlatform используются bounds. Каждый кадр вычисляется Box3 для проверяемых объектов. Поверхность произвольного рельефа этот алгоритм не описывает. |
| Обновления | BridgeUpdateService проверяет первые три строки BRIDGE-UPDATES/1 с RSA PKCS#1 v1.5/SHA-256, длину и SHA-256 HTML. Перед активацией проверяет staged-файл повторно. active.version и previous.version определяют запуск и откат. Обновляется один studio.html. |

## Play с v0.18.4

Родитель читает исходник выбранной загрузчиком Three.js и встраивает его в документ игры. При наличии локального кэша сеть не нужна. Iframe имеет только allow-scripts, opaque origin и no-referrer. Политика CSP отключает connect, формы, workers, внешние скрипты и вложенные фреймы. Ввод и диагностика передаются через postMessage. Редактор принимает сообщения текущего игрового окна с ожидаемым origin и ограниченным текстом. Stop отзывает blob URL. Sandbox запрещает навигацию верхнего окна. Длительный пользовательский JS всё ещё способен нагружать браузер; лимита CPU нет.

## Воспроизводимая сборка

Из корня репозитория: `python tools/build_studio.py --output studio.html`. Для проверки релиза используйте `python tools/build_studio.py --check updates/v0.18.4/studio.html`. Шаблон, редактор, загрузчик GLB, игровой runtime и оба ядра хранятся в src. Демо-модель хранится в assets. Редактор и игровая сборка получают один исходник каждого общего ядра. Работайте с src, затем собирайте новый каталог версии.
